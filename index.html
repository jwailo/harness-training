Part 1

Why Claude?

You're already using Gemini effectively. Here's why we're adding Claude to the toolkit — and what it unlocks.

This isn't about replacing Gemini

Gemini is a capable AI tool. But the system we've built — the Harness Framework — is designed around Claude's specific capabilities. The two key things Claude has that make this work:

  • MCP (Model Context Protocol) — Claude can directly read and write to tools like Linear, Google Drive, and GitHub. This means Claude Chat can create task cards, and Claude Code can read them and update their status — all without you copying and pasting anything.
  • Claude Code — a dedicated coding agent that lives in your terminal or IDE. It reads files, writes code, runs tests, and interacts with Linear. It's separate from Claude Chat (the conversational AI), and that separation is what creates quality.

What changes in your workflow

BEFORE (Gemini)
You describe what you want → Gemini helps → you manually track progress → next session starts from zero → you re-explain context
AFTER (The Harness)
You describe what you want → Claude Chat creates cards in Linear → Claude Code reads cards and builds → Linear remembers everything → next session picks up where you left off

The tools you'll be using

→ Claude Chat (claude.ai) — the strategist. You already know this one. It plans, writes specs, and creates task cards.
→ Claude Code — the builder. A coding agent that runs in your IDE. It reads task cards from Linear and writes the code.
→ Linear — the shared memory. A project management tool that both Claude Chat and Claude Code can read and write to.
→ Antigravity — the IDE. A VS Code fork with built-in AI agent support and MCP connections.

What is Claude Code?

You know Claude Chat — the conversational AI. Claude Code is its counterpart for building things.

Claude Chat vs Claude Code

CLAUDE CHAT

Good at: strategy, planning, writing, analysis
Creates: documents, specs, task cards
Lives in: your browser
CLAUDE CODE
Coding agent that runs in your IDE
Good at: writing code, running tests, file management
Creates: code, tests, deployments
Lives in: Antigravity (your IDE)

How Claude Code works

Claude Code sits inside your IDE (Antigravity) as a panel. You give it an instruction — either by typing directly or by pointing it at a Linear card — and it:

  • Reads your project files to understand the codebase
  • Writes code based on the instruction
  • Runs tests to verify its work
  • Fixes any issues it finds
  • Reports back when it's done

The key difference from asking Claude Chat to write code: Claude Code actually sees your files, runs your tests, and modifies your project directly. Claude Chat just gives you text to copy-paste.

You don't need to be technical

Claude Code does the technical work. Your job is to give it clear instructions (which is what the card system is for) and review the output. You're the director, not the coder.

Part 4

The Philosophy

Why most people hit a ceiling with AI — and how to break through it.

The problem with AI tools alone

Whether you're using Gemini, Claude Chat, or any other AI tool, you've probably noticed:

  • Every new session starts from zero — it doesn't remember what you did yesterday
  • Complex projects drift — the AI loses track of the big picture
  • You become a relay station — copying context between sessions
  • Quality is inconsistent — sometimes it skips tests, cuts corners, or goes off-brief

The Harness solves this by adding two things around your AI tools: a strategy layer and a memory layer.

Three-Layer Architecture

┌─────────────────────────────────────────────────────┐ │ THE HARNESS │ │ │ │ ┌──────────┐ ┌──────────────┐ ┌────────────┐ │ │ │ YOU │──▶│ CLAUDE CHAT │ │CLAUDE CODE │ │ │ │ │ │ (Strategist) │ │ (Builder) │ │ │ │ • Ideas │ │ • Planning │ │ • Code │ │ │ │ • Review │ │ • Cards │ │ • Tests │ │ │ │ • Deploy │ │ • Specs │ │ • Chaining │ │ │ └──────────┘ └──────┬───────┘ └─────┬──────┘ │ │ │ │ │ │ ┌──────┴──────────────────┴──────┐ │ │ │ LINEAR (Shared Memory) │ │ │ │ Cards │ Docs │ Status │ Deps │ │ │ └────────────────────────────────┘ │ └─────────────────────────────────────────────────────┘

You generate ideas, make decisions, review output.
Claude Chat does strategy — planning, specs, creating task cards.
Claude Code does execution — reads cards, writes code, runs tests.
Linear is the shared memory that connects them all.

Core principle

Claude Chat creates. Claude Code executes. Linear remembers. Never mix the roles. The strategy layer does the thinking, the build layer does the doing. The separation is what creates quality.

The rules

→ Don't let Claude push work back to you. If it says "you'll need to manually…" — stop and say "no, you do it."
→ Cards are the prompt. Don't write prompts separately. Write a good Linear card and tell Claude Code to read it.
→ Linear is persistent memory. It's not just task tracking — it's how AI remembers across sessions.
→ Use APIs/CLIs over UIs. Anything the AI can do programmatically, it should.
→ Anything done 3x becomes a hook. If you keep telling the AI the same thing, automate it.
→ One kickoff prompt, not twenty. Claude Code chains through cards autonomously.
Part 5

Linear — AI Memory, Not Just Task Management

You might know Linear as a project management tool. In the Harness, it's something more.

Why Linear specifically?

Linear has an MCP (Model Context Protocol) integration, which means both Claude Chat and Claude Code can read and write to it programmatically. This is the key differentiator — your AI tools can directly access your project board, read card descriptions, update statuses, and leave comments. No copy-pasting. No context loss.

Other tools (Jira, Notion, Trello) could theoretically work, but Linear's MCP is the most mature and it's fast. Speed matters when the AI is reading dozens of cards per session.

How Linear works (quick primer)

If you haven't used Linear before, here's what matters:

  • Workspace — your top-level account (e.g. "Ailo" or your personal workspace)
  • Teams — groups within a workspace (e.g. "GTM", "Engineering")
  • Projects — a collection of related work (e.g. "Ailo Access Demo", "Data Enrichment")
  • Issues (Cards) — individual units of work with descriptions, labels, status, and dependencies
  • Documents — long-form docs that live inside a project (e.g. the Harness Framework doc itself)

The hierarchy is: Workspace → Team → Project → Cards + Docs

Cards as prompts

This is the biggest mental shift. A Linear card isn't just a to-do item — it's a self-contained instruction set for Claude Code. Every card should have:

FieldWhat it does
ContextWhy this card exists, what it connects to
RequirementsSpecific, implementable specs — not vague goals
DependenciesWhich cards must be done first (set via blocking relationships)
Definition of DoneHow Claude Code knows it's finished
LabelAgent, Claude Chat, or Manual — who executes this card

If a card is underspecced, Claude Code will stall and ask questions. Then you're back to being a relay. Good cards = autonomous execution.

The label system

Every card gets exactly one label that determines who executes it:

Agent Claude Code builds it — code, tests, implementation
Claude Chat Claude Chat handles it — specs, strategy, documents
Manual You do it — screenshots, meetings, visual review, deployment

Claude Code only picks up Agent cards. It skips everything else. If an Agent card is blocked by a Manual card that isn't done, it moves to the next unblocked card.

Part 6

Antigravity — Your IDE

Why we use Antigravity instead of VS Code or Cursor.

What is Antigravity?

Antigravity is a VS Code fork built specifically for AI-assisted development. It looks and feels like VS Code (same extensions, same shortcuts, same file tree), but it has native MCP support for connecting to tools like Linear. If you've used VS Code before, the switch is seamless.

Important: Claude Code runs in the Terminal, not the built-in panel

Antigravity has its own built-in AI panel (bottom right). Do not use this — it uses Antigravity's own credits and is not Claude Code.

Claude Code runs in the Terminal inside Antigravity. Here's how to set it up:

1

Open a terminal

In Antigravity: Terminal → New Terminal (or press Ctrl + `)

2

Install Claude Code (one-time only)

npm install -g @anthropic-ai/claude-code
3

Launch Claude Code in dangerous mode

claude --dangerously-skip-permissions

This skips all confirmation prompts so Claude Code runs autonomously. Use this every time you start a session.

4

First time: log in

The first time you run claude, it will ask you to authenticate. Select "Claude account with subscription", then "Login method 1", and authorise in the browser.

Key concept

Antigravity is the environment (where your files and terminal live). Claude Code is the builder (runs in the terminal). Claude Chat is the strategist (runs in claude.ai). Linear is the memory (connects them all). Don't mix them up.

Part 7

Connecting the MCPs

MCP (Model Context Protocol) is how Claude Code talks to Linear. Let's wire it up.

What is MCP?

MCP is a protocol that lets AI tools connect to external services. Instead of you copy-pasting a Linear card description into Claude Code, MCP lets Claude Code read the card directly. It can also update card status, leave comments, and create new cards — all programmatically.

Think of it as giving Claude Code login credentials to your Linear board.

Step 1: Get your Linear API key

1

Open Linear

Go to linear.app in your browser

2

Navigate to Settings → API

Click your avatar (bottom left) → Settings → API → Personal API keys

3

Create a key

Name it something like "Claude Code" and copy it. You'll only see it once.

Step 2: Configure Antigravity

1

Open MCP settings

In Antigravity, go to Manage MCPs → click "View raw config"

2

Paste this config

{ "mcpServers": { "linear": { "command": "npx", "args": ["-y", "mcp-linear"], "env": { "LINEAR_API_KEY": "paste-your-key-here" } } } }
3

Save and refresh

Save the file (Cmd+S), go back to Manage MCPs, click Refresh. The Linear server should appear.

Step 3: Verify it works

Open Claude Code in Antigravity and type:

List all issues in the GTM team.

If it returns your Linear cards, the MCP is connected. If it errors, check your API key is correct and the config file has no syntax errors.

Claude Chat MCP

Claude Chat (claude.ai) also has Linear MCP — it's configured in the Project settings, not in Antigravity. When you set up your Claude Chat project, connect Linear there too. This lets the strategist create and read cards directly.

Part 8

Creating Cards That Work as Prompts

The quality of your cards determines whether Claude Code can work autonomously or keeps asking you questions.

A bad card vs a good card

❌ BAD CARD
Build the login page
Make it look nice and work with our auth system.
✓ GOOD CARD
Build login page with Supabase Auth
Context: First screen users see. Must handle email/password login via Supabase Auth.
Requirements: Email + password fields, error states, redirect to /dashboard on success, "forgot password" link.
Tech: React + Tailwind, use existing Supabase client from src/lib/supabase.ts
Definition of Done: Playwright test passes for login flow, error state displays on bad credentials.

The bad card forces Claude Code to guess. The good card tells it exactly what to build, how to build it, and how to verify it's done.

Card template

Every Agent card should follow this structure:

## Context [Why this card exists. What it connects to in the broader project.] ## Requirements [Specific, implementable specs. Not vague goals.] 1. [Requirement 1] 2. [Requirement 2] 3. [Requirement 3] ## Tech notes [Which files to modify, which patterns to follow, any constraints.] ## Definition of Done - [How Claude Code knows it's finished] - [What tests should pass] - [What the output should look like]

The dependency graph

Cards don't exist in isolation. Use Linear's blocking relationships to create an execution order:

Project Setup
→
Data Model
→
Login Page
→
Dashboard

Claude Code reads these relationships and executes in order. If "Login Page" is blocked by "Data Model," it won't start until the data model card is Done.

The batch execution prompt

Once all cards are created and pre-build blockers are done, you give Claude Code one prompt:

Work through the [Project Name] project in Linear (team: GTM). Only pick up cards labelled "Agent". Skip Manual and Claude Chat cards. Read the dependency graph and execute Agent cards in order. For each: 1. Read the card description from Linear 2. Implement the requirements 3. Verify build passes clean 4. Mark the card as Done with a comment summarising what was done 5. Pick up the next unblocked Agent card If all Agent cards are blocked by non-Agent cards, stop and tell me. Stop and ask if you hit a decision not covered in the card spec.

That's it. One prompt. Claude Code chains through your entire project.

Part 9

Hooks — Automated Guardrails

Hooks are scripts that run automatically during Claude Code sessions. They enforce discipline so you don't have to.

Why hooks matter

Without hooks, Claude Code can:

  • Skip tests to move faster
  • Forget to commit after making changes
  • Create cards without proper context
  • Move to the next card without reviewing quality

Hooks are guardrails for the AI, not for you. They fire automatically at specific moments in the session and enforce the rules you'd otherwise have to remember to enforce manually.

The hook system

HookWhen it firesWhat it does
session-start-reminderSession startsChecks CLAUDE.md exists, uncommitted files, current branch
post-edit-qaAfter 15+ file editsReminds to commit work
post-card-done-deepcodeCard marked DoneTriggers code review before moving on
post-card-verifyCard createdChecks card has project, labels, dependencies
pre-card-createBefore creating a cardBlocks creation if no CLAUDE.md (no project context)
user-prompt-feedbackEvery promptWarns on "just do it" / "skip tests" patterns

Where hooks live

Hooks are shell scripts stored in your project repo:

your-project/ ├── .claude/ │ ├── hooks/ │ │ ├── session-start-reminder.sh │ │ ├── post-edit-qa.sh │ │ ├── post-card-done-deepcode.sh │ │ ├── post-card-verify.sh │ │ ├── pre-card-create.sh │ │ └── user-prompt-feedback.sh │ └── settings.json ← wires hooks to events ├── CLAUDE.md ├── PROGRESS.md └── [your project files]

The settings.json file tells Claude Code when to run each hook. You'll get a pre-built package with all of these — just extract into your project root.

Don't skip this

Hooks are the difference between "Claude Code that sometimes works" and "Claude Code that consistently works." They catch the mistakes before they compound. Install them on every project.

Part 10

CLAUDE.md — Project Instructions for the AI

Every project needs a CLAUDE.md file. It's the first thing Claude Code reads when it starts a session.

What goes in CLAUDE.md

Think of CLAUDE.md as the onboarding doc you'd give a new developer joining your project. It tells Claude Code:

  • What the project is and what it does
  • The tech stack and folder structure
  • Development rules (testing, deployment, things to never do)
  • How to interact with Linear (read cards, update status, follow dependencies)
  • A reference back to the Harness Framework doc for process context

Template

# [Project Name] — Instructions for Claude Code ## Harness Framework This project follows the Harness Framework v4. Read the full framework document in Linear (ASET project, document: "The Harness Framework v4") for process context. ## Project Overview [What this project is and what it does] ## Tech Stack [List all technologies, frameworks, services] ## Development Rules ### After EVERY code change: 1. Run the test suite 2. Read the output carefully 3. If any test fails → fix it → re-run 4. Only report "done" when ALL tests pass ### Linear Integration: - Cards are the prompt — read them for requirements - Only pick up cards labelled "Agent" - Mark cards Done with a summary comment - Follow the dependency graph - If blocked, skip to next unblocked Agent card ### Things to NEVER do: - Delete user data without confirmation - Push to production without testing - Skip tests to save time - Work on non-Agent cards
The reference loop

CLAUDE.md points to the Harness Framework doc in Linear. The Harness doc contains the CLAUDE.md template. The first card in every project creates the CLAUDE.md. The system bootstraps itself.

The Philosophy

Why most people hit a ceiling with AI — and how to break through it

The problem with AI tools alone

Whether you're using Claude Chat, ChatGPT, or any other AI tool, you've probably noticed:

→ Every new session starts from zero — it doesn't remember what you did yesterday
→ Complex projects drift — the AI loses track of the big picture
→ You become a relay station — copying context between sessions
→ Quality is inconsistent — sometimes it skips steps, cuts corners, or goes off-brief

The Harness solves this by adding two things around your AI tools: a strategy layer and a memory layer.

Three-Layer Architecture

┌─────────────────────────────────────────────────────┐ │ THE HARNESS │ │ │ │ ┌──────────┐ ┌──────────────┐ ┌────────────┐ │ │ │ YOU │─▶│ CLAUDE CHAT │ │CLAUDE CODE │ │ │ │ │ │ (Strategist) │ │ (Builder) │ │ │ │ • Ideas │ │ • Planning │ │ • Code │ │ │ │ • Review │ │ • Cards │ │ • Tests │ │ │ │ • Deploy │ │ • Specs │ │ • Chaining │ │ │ └──────────┘ └──────┬───────┘ └─────┬──────┘ │ │ │ │ │ │ ┌────────────┴────────────────┴──────┐ │ │ │ LINEAR (Shared Memory) │ │ │ │ Cards │ Docs │ Status │ Deps │ │ │ └────────────────────────────────────┘ │ └─────────────────────────────────────────────────────┘

You generate ideas, make decisions, review output.
Claude Chat does strategy — planning, specs, creating task cards.
Claude Code does execution — reads cards, writes code, runs tests.
Linear is the shared memory that connects them all.

Core principle

Claude Chat creates. Claude Code executes. Linear remembers. Never mix the roles. The strategy layer does the thinking, the build layer does the doing. The separation is what creates quality.

The rules

→ Don't let Claude push work back to you. If it says "you'll need to manually…" — stop and say "no, you do it."
→ Cards are the prompt. Don't write prompts separately. Write a good Linear card and tell Claude Code to read it.
→ Linear is persistent memory. It's not just task tracking — it's how AI remembers across sessions.
→ Use APIs/CLIs over UIs. Anything the AI can do programmatically, it should.
→ Anything done 3x becomes a hook. If you keep telling the AI the same thing, automate it.
→ One kickoff prompt, not twenty. Claude Code chains through cards autonomously.

The Tools

Four tools, each with a specific role

The Strategist

Claude Chat

Conversational AI at claude.ai. Plans, writes specs, and creates task cards in Linear. Lives in your browser.

The Builder

Claude Code

Coding agent that runs in your terminal. Reads Linear cards, writes code, runs tests, and chains through tasks autonomously.

The Memory

Linear

Project management tool that both Claude Chat and Claude Code can read and write to. The shared memory that persists across sessions.

The Environment

Antigravity

A VS Code fork with native MCP support. Where your files live and where Claude Code runs in the terminal.

Claude Chat vs Claude Code

This is the most important distinction. Claude Chat (the browser AI) is the strategist — it plans, creates cards, and makes decisions. Claude Code is the builder — it reads those cards, writes actual code in your project, runs tests, and modifies files directly.

The key difference: Claude Code actually sees your files, runs your tests, and modifies your project. Claude Chat just gives you text. Keeping them separated is what makes the system reliable.

You don't need to be technical. Claude Code does the technical work. Your job is to give it clear instructions (which is what the card system is for) and review the output. You're the director, not the coder.

How they connect

MCP (Model Context Protocol) is the glue. It lets Claude Chat and Claude Code both talk to Linear programmatically — reading cards, updating status, creating new cards. No copy-pasting. No context loss.

Think of MCP as giving your AI tools login credentials to your project board. We'll set this up in the setup section.

Understand

Linear as AI Memory

Cards are prompts, not to-do items

This is the biggest mental shift. A Linear card isn't just a task — it's a self-contained instruction set for Claude Code. The better the card, the more autonomously Claude Code can execute.

The Linear hierarchy

Workspace → Team → Project → Cards

Workspace — your top-level account. Teams — groups within a workspace. Projects — a collection of related work. Cards (Issues) — individual units of work with descriptions, labels, status, and dependencies. Documents — long-form docs that live inside a project.

What goes in a card

Claude Chat creates these for you — you describe what you want and it writes properly structured cards. But here's what each card contains:

FieldWhat it does
ContextWhy this card exists, what it connects to in the broader project
RequirementsSpecific, implementable specs — not vague goals
DependenciesWhich cards must be done first (set via blocking relationships)
Definition of DoneHow Claude Code knows it's finished
LabelAgent, Claude Chat, or Manual — who executes this card

You don't need to write cards yourself. Claude Chat handles card creation, structuring, and quality. Your job is to describe what you want built clearly enough for Claude Chat to create good cards.

The label system

Every card gets exactly one label that determines who executes it:

LabelWho executes
AgentClaude Code builds it — code, tests, implementation
Claude ChatClaude Chat handles it — specs, strategy, documents
ManualYou do it — screenshots, meetings, visual review, deployment

Claude Code only picks up Agent cards. It skips everything else. If an Agent card is blocked by a Manual card that isn't done, it moves to the next unblocked card.

The dependency graph

Cards don't exist in isolation. Claude Chat sets up blocking relationships to create an execution order:

Project Setup → Data Model → Login Page → Dashboard

Claude Code reads these relationships and executes in order. You give it one kickoff prompt and it chains through the entire project.

Setup

Accounts & Downloads

Let's get everything installed

Before we connect anything, you need four things set up on your machine. We'll go through each one.

1

Node.js (prerequisite)

Claude Code's MCP servers require Node.js to run. Download the LTS version from nodejs.org and install it. After installing, open a terminal and run node --version — you should see v18 or higher.

2

Linear account

Go to linear.app and sign up. The free plan supports up to 250 issues — more than enough to start. Create a workspace, then a team inside it (e.g. "GTM"), then a project inside the team.

3

Claude account

You'll need a Claude Pro subscription (or higher) at claude.ai. This gives you access to both Claude Chat in the browser and Claude Code in the terminal. If you already have an account, make sure your subscription is active.

4

Antigravity (IDE)

Download from anti-gravity.dev. Drag to Applications and open it. It looks and feels like VS Code — same extensions, same shortcuts, same file tree. If you've used VS Code before, the switch is seamless.

Important — Antigravity's built-in panel

Antigravity has its own built-in AI panel (usually bottom right). Do not use this — it uses Antigravity's own credits and is not Claude Code. Claude Code runs in the Terminal inside Antigravity, which we'll set up in a later step.

Setup

Connecting the MCPs

Wire Linear into your tools

MCP (Model Context Protocol) is how Claude Code and Claude Chat both talk to Linear. We need to connect it in two places: Antigravity (for Claude Code) and Claude Chat (for the strategist).

Part A: Get your Linear API key

1

Open Linear settings

Go to linear.app → click your avatar (bottom left) → Settings → API → Personal API keys

2

Create a key

Name it something like "Claude Code" and copy it. You'll only see it once — save it somewhere safe (e.g. 1Password as a Secure Note).

Part B: Configure Linear MCP in Antigravity

1

Open MCP settings

In Antigravity: press Cmd+Shift+P → type "MCP" → Manage MCP Servers → click "View raw config"

2

Paste this config

{ "mcpServers": { "linear": { "command": "npx", "args": ["-y", "mcp-linear"], "env": { "LINEAR_API_KEY": "lin_api_PASTE_YOUR_KEY_HERE" } } } }
3

Save and refresh

Save the file (Cmd+S), go back to Manage MCPs, click Refresh. The Linear server should appear.

Part C: Connect Linear MCP to Claude Chat

1

In Claude Chat

Go to claude.ai → Settings → Connectors → Browse → search "Linear" → Connect. Ask an org admin to enable it if needed. This lets the strategist create and read cards directly.

Verify it works

Open Claude Code in Antigravity's terminal and type:

List all issues in the [your team name] team.

If it returns your Linear cards, the MCP is connected. If it errors, check your API key is correct and the config file has no syntax errors.

Setup

Claude Chat Project

Set up the strategist

Claude Chat needs a project with custom instructions so it knows to work within the Harness Framework. This is what turns general-purpose Claude into your strategist.

1

Create a Claude Chat project

Go to claude.ai → Projects → Create. Name it "Building with AI" (or whatever suits you).

2

Paste the system instructions

In the project's custom instructions field, paste the following:

You are a strategic AI assistant working within the Harness Framework v4. Your role is Layer 1 (Strategist): you help with planning, architecture, card creation, and decision-making. CRITICAL RULES: - NEVER build artifacts, write code, or create files directly. - ALWAYS create Linear cards first. Cards are the work. - Before starting ANY new project, read the Harness Framework v4 document from Linear and follow the New Project Setup Checklist. - Do NOT proceed until you have read the process document. When the user describes something they want to build: 1. Ask clarifying questions first 2. Read the Harness Framework v4 doc from Linear 3. Create a Linear project with properly structured cards 4. Each card must have: Context, Requirements, Definition of Done, Label (Agent/Claude Chat/Manual), Dependencies 5. Give the user a kickoff prompt to paste into Claude Code You do NOT write code — that's Claude Code's job. Claude Code reads the cards and builds them. You create the cards and manage the strategy. Linear team: [your team name] Linear project: [varies per project]
3

Verify Claude Chat + Linear

In your project, ask "Please list my Linear issues". If it returns results, the connection works.

Why a project?

Claude Chat projects let you set persistent instructions that apply to every conversation within that project. Without a project, you'd have to re-explain the Harness every time you start a new chat.

Setup

Claude Code

Install the builder

Claude Code runs in the terminal inside Antigravity. Here's how to install and launch it.

1

Open a terminal in Antigravity

Terminal → New Terminal (or press Ctrl + `). Remember: use the terminal, not the built-in AI panel.

2

Install Claude Code

The recommended method is the native installer (no Node.js dependency for Claude Code itself):

curl -fsSL https://claude.ai/install.sh | bash

If you're on Windows, use PowerShell: irm https://claude.ai/install.ps1 | iex

Why we still installed Node.js

Claude Code itself no longer requires Node.js. But the Linear MCP server runs via npx, which does require Node.js. That's why we installed it in the prerequisites step.

3

Launch Claude Code in dangerous mode

claude --dangerously-skip-permissions

This skips all confirmation prompts so Claude Code runs autonomously. Use this command every time you start a session.

4

First time: log in

The first time you run claude, it will ask you to authenticate. Select "Claude account with subscription", then "Login method 1", and authorise in the browser.

Do not confuse these

Antigravity's built-in AI panel (bottom right of the IDE) is NOT Claude Code. It uses Antigravity's own credits. Claude Code runs in the terminal with the claude command. Always use the terminal.

Hooks & CLAUDE.md

Automated guardrails and project context

Hooks — guardrails for the AI

Hooks are scripts that run automatically during Claude Code sessions. They enforce discipline so you don't have to. Without them, Claude Code can skip tests, forget to commit, or move on without reviewing quality.

HookWhat it does
session-start-reminderChecks CLAUDE.md exists, uncommitted files, current branch
post-edit-qaReminds to commit after 15+ file edits
post-card-done-deepcodeTriggers code review before moving to next card
post-card-verifyChecks card has project, labels, dependencies
pre-card-createBlocks card creation if no CLAUDE.md (no project context)
user-prompt-feedbackWarns on "just do it" / "skip tests" patterns

These live in .claude/hooks/ in your project repo. You'll get a pre-built package with all of these — just extract into your project root.

CLAUDE.md — project instructions for the AI

Every project needs a CLAUDE.md file in the root. It's the first thing Claude Code reads when it starts a session. Think of it as the onboarding doc you'd give a new developer joining your project.

It tells Claude Code: what the project is, the tech stack, development rules (testing, deployment, things to never do), how to interact with Linear, and a reference back to the Harness Framework doc.

# [Project Name] — Instructions for Claude Code ## Harness Framework This project follows the Harness Framework v4. Read the full framework document in Linear for process context. ## Project Overview [What this project is and what it does] ## Tech Stack [List all technologies, frameworks, services] ## Development Rules ### After EVERY code change: 1. Run the test suite 2. Read the output carefully 3. If any test fails → fix it → re-run 4. Only report "done" when ALL tests pass ### Linear Integration: - Cards are the prompt — read them for requirements - Only pick up cards labelled "Agent" - Mark cards Done with a summary comment - Follow the dependency graph - If blocked, skip to next unblocked Agent card ### Things to NEVER do: - Delete user data without confirmation - Push to production without testing - Skip tests to save time - Work on non-Agent cards
The reference loop

CLAUDE.md points to the Harness Framework doc in Linear. The Harness doc contains the CLAUDE.md template. The first card in every project creates the CLAUDE.md. The system bootstraps itself.

Your First Run

Put it all together

Everything is installed and connected. Here's how the workflow actually looks in practice.

The workflow

1. Open your Claude Chat project and describe what you want to build.
2. Claude Chat creates structured cards in Linear with proper labels, dependencies, and specs.
3. Open Antigravity and launch Claude Code in the terminal with claude --dangerously-skip-permissions
4. Give Claude Code the kickoff prompt (below).
5. Claude Code chains through all Agent cards, building each one autonomously.
6. You review the output and deploy.

The kickoff prompt

Once all cards are created, paste this into Claude Code:

Work through the [Project Name] project in Linear (team: [your team]). Only pick up cards labelled "Agent". Skip Manual and Claude Chat cards. Read the dependency graph and execute Agent cards in order. For each: 1. Read the card description from Linear 2. Implement the requirements 3. Verify build passes clean 4. Mark the card as Done with a comment summarising what was done 5. Pick up the next unblocked Agent card If all Agent cards are blocked by non-Agent cards, stop and tell me. Stop and ask if you hit a decision not covered in the card spec.

That's it. One prompt. Claude Code chains through your entire project.

Full setup checklist

□ 1. Node.js installed — node --version returns v18+
□ 2. Linear account created — workspace, team, and first project set up
□ 3. Claude Pro subscription active — at claude.ai
□ 4. Antigravity installed — downloaded from anti-gravity.dev
□ 5. Linear API key created — saved securely (you only see it once)
□ 6. Linear MCP configured in Antigravity — paste config into MCP settings
□ 7. Linear MCP connected to Claude Chat — via Settings → Connectors
□ 8. Claude Chat project created — with system instructions pasted
□ 9. Claude Code installed — via native installer in Antigravity terminal
□ 10. Claude Code authenticated — first run, login via browser
□ 11. Test the connection — tell Claude Code to list your Linear issues
□ 12. Run your first card — give Claude Code the kickoff prompt
What happens next

Once this is set up, your workflow becomes: open Claude Chat → describe what you want → Claude Chat creates the cards → open Antigravity terminal → launch Claude Code → paste the kickoff prompt → Claude Code builds everything → you review and deploy.

You're ready.

The Harness Framework v4 doc lives in Linear as the permanent reference. Your Claude Chat project knows the process and will always create cards before building. Claude Code runs in the terminal. And Linear ties it all together as the shared memory.

The goal isn't zero human involvement. It's zero unnecessary human involvement.
